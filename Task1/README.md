# Cписок проблем компании в разрезе работы с данными

1. Отсутствие централизованной системы управления доступом.
   Все данные хранятся на общем диске без разграничения прав доступа.
   Риск: Любой сотрудник может получить доступ к медицинским картам и персональным данным всех пациентов.
2. Отсутствие шифрования данных.
   Excel-файлы и сканы документов хранятся в открытом виде.
   Риск: При компрометации общего диска все данные становятся доступны злоумышленникам.
3. Отсутствие аудита и логирования.
   Нет контроля за действиями пользователей с конфиденциальными данными.
   Риск: Невозможно отследить несанкционированный доступ или изменение данных.
4. Дублирование данных в разных системах.
   Одни и те же данные вводятся в Excel, 1С и хранятся в виде сканов.
   Риск: Увеличение площади атаки, сложность обеспечения права на удаление данных.
5. Передача данных без защищённых каналов.
   Интеграция между ККМ и 1С через незащищённый TCP/IP.
   Риск: Перехват финансовых данных при передаче.
6. Ручная обработка без валидации.
   Все данные вводятся вручную без проверки корректности и полноты.
   Риск: Ошибки ввода, потеря целостности данных.
7. Хранение медицинских данных вместе с идентификаторами.
   В одних файлах хранятся и ФИО, и диагнозы.
   Риск: При утечке сразу раскрывается вся информация о пациенте.
8. Отсутствие резервного копирования и восстановления.
   Нет упоминаний о системе бэкапов.
   Риск: Потеря всех данных при сбое оборудования.
9. Отсутствие процедур удаления данных.
   Нет механизмов для реализации права на забвение.
   Риск: Невозможность выполнить требования пациента об удалении его данных.

# Список данных для защиты и подходящие способы защиты

1. Персональные идентификаторы (PII)

   Данные: ФИО, дата рождения, телефон, email, адрес прописки, место работы/учебы

   Методы защиты:
   * Шифрование при хранении (AES-256)
   * Обфускация при отображении (маскирование)
   * Токенизация для внутренних операций
2. Медицинские данные (PHI)

   Данные: Диагнозы, анамнез, жалобы, результаты анализов, назначения

   Методы защиты:
   * Шифрование при хранении и передаче
   * Обезличивание для аналитики
   * Раздельное хранение от идентификаторов
3. Финансовые данные

   Данные: Сумма платежей, номера договоров, банковские реквизиты

   Методы защиты:
   * Шифрование при хранении и передаче
   * Токенизация номеров карт
   * Обфускация в логах
4. Операционные данные

   Данные: Даты приемов, номера кабинетов, время записи

   Методы защиты:
   * Шифрование в базе данных
   * Ограничение доступа по ролям.

# Механизм тегирования данных

Система тегов по чувствительности:
* PII — персональные данные
* PHI — медицинские данные
* FIN — финансовые данные
* INTERNAL — внутренние данные
* PUBLIC — публичные данные

Система тегов по обработке:
* ENCRYPT — требует шифрования
* MASK — требует маскирования
* AUDIT — требует аудита доступа
* RETENTION — ограниченное время хранения
* DELETE — подлежит удалению по запросу

Система тегов по доступу:
* DOCTOR_ONLY — доступ только врачам
* RECEPTION_ONLY — доступ только ресепшену
* FINANCE_ONLY — доступ только финансовым службам
* PATIENT_OWNER — доступ только владельцу данных

# Инструменты и меры обеспечения конфиденциальности
1. Управление доступом
   * Keycloak — централизованная аутентификация и авторизация
   * RBAC/ABAC — ролевое и атрибутное управление доступом
   * Multi-factor Authentication — двухфакторная аутентификация
2. Шифрование и защита данных
   * HashiCorp Vault — управление секретами и ключами
   * Database encryption — шифрование на уровне БД (PostgreSQL TDE)
   * Application-level encryption — шифрование в приложении
3. Аудит и мониторинг
   * ELK Stack — сбор и анализ логов
   * Prometheus + Grafana — мониторинг доступа к данным
   * Data Loss Prevention (DLP) — предотвращение утечек
4. Обработка данных
   * Data masking tools — инструменты маскирования данных
   * Anonymization services — сервисы обезличивания
